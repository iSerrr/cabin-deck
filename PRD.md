# PRD: Cab Deck — планшетна панель керування для ETS2 (пілот)

Oct 4, 2026 · @Liub · v3 (vJoy, віддалена діагностика)

> Цільова гра — American Truck Simulator. ETS2 працює так само: той самий движок SCS, vJoy і SDK. Далі в тексті «ETS2» означає будь-яку з двох ігор.

## Суть і мета

Пілот перевіряє одну гіпотезу: кнопка, натиснута у браузері планшета, спрацьовує в Euro Truck Simulator 2 як кнопка окремого ігрового пристрою, без встановлення застосунку на планшет.

На ПК запускається Python-програма. Вона роздає веб-сторінку з панеллю кнопок у локальній мережі й перетворює дотики на натискання кнопок віртуального джойстика vJoy. Гра бачить vJoy як звичайний контролер, і дії на його кнопки призначаються в меню керування гри.

Кожна кнопка панелі має стабільний ID виду `cab_deck_btn_NNN`, де `NNN` — номер кнопки vJoy. Наприклад, `cab_deck_btn_007` — це кнопка 7 пристрою vJoy.

Пілот вважається вдалим, якщо за одну ігрову сесію панеллю можна керувати допоміжними функціями вантажівки (світло, двірники, поворотники, вікна) і не тягнутися до клавіатури.

## Межі пілота

| Входить у пілот | Не входить (наступні етапи) |
| --- | --- |
| Python-сервер на ПК з Windows | Власний плагін SCS SDK з іменованими входами |
| Віртуальний джойстик vJoy, лише кнопки | Осі vJoy: повзунки, кермо, педалі |
| Одна сторінка панелі на простому HTML/JS | React, кілька сторінок-табів |
| 12 кнопок двох типів: натискання й утримання | Перемикачі на кілька положень |
| Розкладка кнопок у JSON-файлі | Візуальний редактор панелі |
| Режим `--dry-run` для розробки без Windows і vJoy | Телеметрія з гри, підсвітка реального стану |
| Один планшет у домашній Wi-Fi мережі | Кілька пристроїв, доступ через інтернет |
| Індикатор з'єднання й автоперепідключення | Авторизація, HTTPS |

## Сценарій використання

Від запуску до першого натискання в грі має проходити не більше хвилини.

1. Користувач запускає на ПК одну команду: `python server.py`.
2. Сервер друкує в консолі всі локальні IPv4-адреси з портом: `http://192.168.x.x:8000`.
3. Користувач відкриває цю адресу в браузері планшета. Планшет і ПК в одній Wi-Fi мережі.
4. Панель показує сітку кнопок і зелений індикатор з'єднання.
5. Користувач запускає ETS2.
6. Дотик до кнопки на планшеті виконує дію в грі.
7. Якщо з'єднання зникає, індикатор стає червоним, а панель сама перепідключається.

### Одноразове налаштування

1. Встановити драйвер vJoy (форк, сумісний з Windows 10/11).
2. У `Configure vJoy` для пристрою 1 задати кількість кнопок не менше 32 (за замовчуванням їх 8).
3. Дозволити порт 8000 у брандмауері Windows для приватної мережі.
4. У грі: «Параметри → Керування» — додати vJoy як пристрій вводу й призначити дії на кнопки. Щоб призначити кнопку, у режимі призначення торкнутися її на планшеті.
5. На планшеті вимкнути автоблокування екрана.

## Архітектура

```
Планшет (браузер) ──WebSocket──► server.py ──pyvjoy──► драйвер vJoy ──► ETS2
                                     │
                                 config.json
```

Планшет шле лише ID кнопки й тип події. Сервер перевіряє ID за конфігом і сам вирішує, яку кнопку vJoy натиснути, тому з клієнта не можна передати довільний ввід.

### Стек

| Компонент | Технологія | Навіщо |
| --- | --- | --- |
| Сервер | FastAPI + uvicorn | HTTP і WebSocket в одному процесі |
| Ввід | vJoy + `pyvjoy` | Окремий ігровий пристрій, без конфліктів з клавіатурою |
| Панель | HTML, CSS, JS без збірки | Для пілота досить одного файлу |
| Конфіг | `config.json` | Розкладка без правки коду |

### Протокол

Повідомлення йдуть як JSON через WebSocket.

| Напрям | Повідомлення | Коли |
| --- | --- | --- |
| Сервер → планшет | `{"type": "layout", "grid": {...}, "buttons": [...]}` | Одразу після підключення |
| Планшет → сервер | `{"id": "cab_deck_btn_007", "event": "down"}` | Палець торкнувся кнопки |
| Планшет → сервер | `{"id": "cab_deck_btn_007", "event": "up"}` | Палець відпустив кнопку |
| Планшет → сервер | `{"type": "ping"}` → `{"type": "pong"}` | Кожні 2 с |
| Планшет → сервер | `{"type": "client_error", "message": "..."}` | JS-помилка на панелі |

Для кнопки `tap` сервер на `down` ставить кнопку vJoy у стан «натиснута» й відпускає її через `tap_ms` (типово 80 мс, щоб гра встигла побачити натискання навіть при низькому FPS). Подію `up` для `tap` сервер ігнорує. Для `hold` кнопка натиснута від `down` до `up` або до `hold_timeout_s`. Затримки реалізуються через `asyncio`, без блокування сервера.

### Конфіг

```json
{
  "vjoy_device": 1,
  "tap_ms": 80,
  "hold_timeout_s": 10,
  "grid": {"cols": 4, "rows": 3},
  "buttons": [
    {"id": "cab_deck_btn_001", "label": "Фари", "icon": "💡", "color": "#f5c542", "type": "tap"},
    {"id": "cab_deck_btn_007", "label": "Сигнал", "icon": "📯", "color": "#e05252", "type": "hold"}
  ]
}
```

Номер кнопки vJoy береться з ID: `cab_deck_btn_007` → кнопка 7. Окремого поля для номера немає, тож розійтися ID і номер не можуть. ETS2 рахує кнопки джойстика з нуля, тому в меню гри ця кнопка показується як Button 6.

## Нефункціональні вимоги

Головна вимога — затримка: від дотику до реакції в грі не більше 100 мс у домашній Wi-Fi мережі.

- **Платформа ПК:** Windows 10 або 11, Python 3.10+, встановлений vJoy.
- **Розробка:** сервер і панель розробляються на macOS у режимі `--dry-run`. Реальний ввід перевіряється на Windows-ПК.
- **Планшет:** будь-який сучасний браузер (Chrome на Android, Safari на iPad), без встановлення застосунків.
- **Мережа:** тільки локальна. Сервер не має бути доступний з інтернету.
- **Безпека:** сервер виконує лише дії з `config.json`. Довільний ввід з клієнта передати не можна, тільки ID кнопки.
- **Надійність:** жодна кнопка не лишається затиснутою після розриву з'єднання, закриття сторінки або зупинки сервера.
- **Запуск:** одна команда, залежності ставляться через `pip install -r requirements.txt`.
- **Розширюваність:** нова кнопка додається рядком у `config.json` і призначенням у грі, без правки коду.
- **Діагностика:** стан і лог сервера на Windows можна прочитати з Mac через `/api/health` і `/api/logs`, без доступу до екрана ПК.

## Ризики

Найбільший ризик — гра не бачить vJoy або не дає призначити дії на його кнопки. Його перевіряє `spike_vjoy.py` ще до верстки панелі.

| Ризик | Наслідок | Що робимо |
| --- | --- | --- |
| ETS2 не бачить vJoy або не призначає кнопки | Пілот не працює | Спайк першим кроком. Запасні варіанти: імітація клавіатури (`pydirectinput`) або власний плагін SCS SDK |
| Драйвер vJoy не ставиться на Windows 11 | Немає пристрою | Брати підтримуваний форк vJoy, описати версію в README |
| Версія `vJoyInterface.dll` у `pyvjoy` не збігається з драйвером | Помилка при старті | Підкласти DLL з папки встановленого vJoy, описати в README |
| У vJoy налаштовано лише 8 кнопок | Кнопки 9–12 не працюють | Крок у README. Перевірка S8 при старті |
| Гра ігнорує джойстик, коли вікно не у фокусі | Натискання не доходять | Перевірити в спайку. Якщо так, описати в інструкції |
| Брандмауер блокує порт | Планшет не відкриває сторінку | Правило для порту 8000 у приватній мережі, крок в інструкції |
| Кнопка «залипає» після розриву Wi-Fi або сну вкладки | Сигнал або вікно працюють безкінечно | Вимоги S5, S7 і P3 |
| Браузер планшета масштабує або прокручує сторінку | Хибні дотики | Вимоги P5 і P6, перевірка на реальному планшеті |
| Панель не знає реального стану (фари ввімкнені чи ні) | Кнопки без підсвітки стану | Прийнято для пілота. Телеметрія на наступному етапі |
| Будь-хто в домашній Wi-Fi може натискати кнопки | Випадкові дії в грі | Прийнято для пілота. Авторизація на наступному етапі |

## Етап 2: зворотний зв'язок з гри (у роботі)

Мета: кнопки панелі показують реальний стан вантажівки в грі.

### Джерело даних

Плагін RenCloud scs-sdk-plugin V.1.12.1 (`scs-telemetry.dll` у `<гра>\bin\win_x64\plugins\`) пише телеметрію в спільну пам'ять `Local\SCSTelemetry`. Сервер читає її через бібліотеку `truck-telemetry`. Одне читання займає ~0.8 мс, тож опитування 10 разів на секунду не навантажує ПК.

### Результати спайку (Oct 4, 2026, ATS, телеметрія гри 1.5)

| Кнопка | Поля телеметрії | Стани на панелі |
| --- | --- | --- |
| Двигун | `electricEnabled`, `engineEnabled` | вимкнено / запалювання / заведено |
| Фари | `lightsParking`, `lightsBeamLow` | вимкнено / габарити / ближнє |
| Дальнє світло | `lightsBeamHigh` | вимк / увімк |
| Лівий / правий поворотник | `blinkerLeftActive` + `blinkerLeftOn` (фаза), так само для правого | вимк / блимає в такт з грою |
| Аварійка | `lightsHazards` + фаза з `blinkerLeftOn` | вимк / блимає |
| Стоянкове гальмо | `parkBrake` | вимк / увімк |
| Двірники | `wipers` — лише увімк/вимк, режим не передається | див. відкрите питання |
| Причіп | `trailer[0].attached` | не перевірено |
| Ретардер | `retarderBrake` з `retarderStepCount` (3 на тестовій вантажівці) | не перевірено |
| Сигнал, вікна | немає в телеметрії | без стану |

Під час аварійки `blinkerLeftActive` і `blinkerRightActive` лишаються `False`, тому аварійку не можна визначати через поворотники.

### Рішення

- **Індикатори.** Сервер опитує телеметрію кожні 100 мс і зводить її до індикаторів з рівнем `off` / `dim` / `on` і необов'язковим текстом («Габарити», «Запалювання»). Кнопка в конфігу посилається на індикатор полем `"indicator": "lights"`. Поворотники й аварійка передають фазу блимання через `dim` / `on`.
- **Двірники — перемикач на 4 положення** (`"type": "switch"`). У ATS є лише дії «Двірники» (вперед) і «Двірники назад», тому панель сама пам'ятає положення. Торкання «3» з положення «1» дає два натискання «вперед». Між натисканнями `switch_gap_ms` (150 мс). Перемикач ніколи не тисне «вперед» на останньому положенні чи «назад» на «Вимк», тож поведінка гри на краях циклу не важлива.
- **Корекція по телеметрії.** Якщо через 1 с після останнього натискання гра показує `wipers: False`, а перемикач не на «Вимк», положення скидається в 0. Якщо двірники працюють, а перемикач на «Вимк», ставиться 1. Помилка можлива лише тоді, коли режим змінили повз панель, і вона виправляється при наступному вимкненні.
- **Стан гри на панелі:** «немає телеметрії» / «не запущена» / «пауза» / «в кабіні».

## Етап 3: пневматика, додаткове світло, сторінки, гаптика (у роботі)

Рішення від Oct 4, 2026. Беремо пневматику й гальма, ACTIVATE, маячок і додаткові фари, сторінки, гаптику. Не беремо: круїз-контроль (є на кермі), інформаційну смугу, камери, радіо, місії.

### Сторінки

| Вкладка | Контроли |
| --- | --- |
| DRIVE | LIGHTS, HIGH BEAM, LEFT, RIGHT, HAZARD, WIPERS, HORN, ENGINE, PARK BRAKE, TRAILER AIR, ACTIVATE |
| AIR & BRAKES | AIR PRESSURE (прилад), RETARDER, ENGINE BRAKE, DIFF LOCK, LIFT AXLE, TRAILER AXLE |

Інтерфейс англійською. Конфіг: `pages` замість `grid` + `buttons`.

### Телеметрія

| Контрол | Поля | Показ |
| --- | --- | --- |
| RETARDER | `retarderBrake`, `retarderStepCount` | точна позиція; зайві положення сховані |
| ENGINE BRAKE | `motorBrake` | вимк / увімк |
| DIFF LOCK | `differentialLock` | вимк / LOCKED |
| LIFT AXLE / TRAILER AXLE | `liftAxleIndicator`, `trailerLiftAxleIndicator` | вимк / RAISED |
| AIR PRESSURE | `airPressure`, `airPressureWarning`, `airPressureEmergency` | значення в psi, шкала, жовтий / червоний стан |
| BEACON | `lightsBeacon` | вимк / увімк |
| AUX FRONT / AUX ROOF | `lightsAuxFront`, `lightsAuxRoof` (0 / 1 / 2) | вимк / dim / on |

Бібліотека `truck-telemetry` перезаписує поріг `airPressureWarning` (float) прапорцем з тією ж назвою (bool). Нам потрібен лише прапорець, тож це не заважає.

### Перемикач з точною позицією

Ретардер — перемикач, як двірники (кнопки vJoy 18 «+» і 19 «−»), але з `"position_source": "retarder"`. Через 1 с після останнього натискання положення береться з гри. Ціль обмежується кількістю ступенів вантажівки: на 3-ступеневому ретардері дотик до «5» зупиниться на 3.

### Гаптика

`navigator.vibrate` на кожен дотик: tap 12 мс, hold 25 мс, сегмент перемикача 10 мс, кожне фактичне перемикання положення 6 мс, вкладка 6 мс, втрата зв'язку — подвійний імпульс. Працює в Android-браузерах. На iPad вібромотора немає, тому там гаптики не буде.

### Вкладка SETUP

Остання вкладка. Список усіх кнопок vJoy з конфігу, відсортований за номером: номер vJoy, номер у грі (на 1 менший), назва контролу, напрям для перемикачів і назва дії в ATS (`action`, `forward_action`, `back_action` у конфігу). Дотик шле `{"type": "bind", "key": "cab_deck_btn_013"}`, сервер робить одне натискання на 150 мс. Ключ звіряється зі списком кнопок конфігу, тож сирий номер передати не можна. Сторінки гортаються свайпом лише по смузі вкладок, щоб свайп не почався на контролі й не натиснув його.

### Дизайн v6 (Oct 4, 2026)

Дизайн Claude Design «Cab Deck v6 Single Screen» перенесено в `static/index.html` на чистий JS без React і без мережевих залежностей. Замість вкладок — один екран 1194×834 з п'ятьма зонами (LIGHTS & SIGNALS, ENGINE & AIR, AXLES & ACTION, CAB, WIPERS / RETARDER), масштабований під екран планшета. SETUP відкривається шестернею або свайпом по табличці статусу.

Зміни відносно прототипу:
- LIGHTS — точний перемикач по колу (`cyclic`, `position_source: lights`): дотик до LOW ставить ближнє, скільки б натискань не було потрібно.
- Блимання поворотників і аварійки береться з фази гри, а не з локального таймера.
- Конфіг став плоским списком `controls`; розкладку задає дизайн, а не конфіг.

### Оздоблення v7 (Oct 5, 2026)

З концепту «Cab Deck v7 Rocker Concept» взято лише візуальну мову: консоль у темно-зеленому кольорі кабіни (або горіх, або графіт v6) з перемикачем у SETUP, кремово-бурштинові легенди, клавіші як чорний пластик рокерів і натискання з перекидом верху клавіші. Розкладку, розміри зон дотику, шрифти й лінзи станів v6 не змінено: сітка рокерів v7 зменшувала лампи стану до 14×6 px і підписи до 11 px. Важелі з перетягуванням додано як режим за замовчуванням для LIGHTS, WIPERS і RETARDER (SETUP → SWITCHES: LEVER / BUTTONS): тап по позиції на доріжці працює як раніше, драг клацає на кожному фіксаторі (звук + вібрація), а команда `set` надсилається один раз, коли палець відпущено. Скасований жест (pointercancel) нічого не надсилає.

### Зміни розкладки (Oct 10, 2026)

- **Ретардер прибрано** з панелі, конфігу й сервера. Кнопки vJoy 18 і 19 вільні.
- **Поворотники** — компактні кнопки (210×58) зліва й справа від таблички статусу. HIGH BEAM і HAZARD у зоні LIGHTS & SIGNALS стали вдвічі вищими.
- **FUEL** на місці ретардера: запас ходу (`fuelRange`), рівень (`fuel` / `fuelCapacity`), середня витрата (`fuelAvgConsumption`), лампа `fuelWarning`. SDK віддає літри й кілометри; панель показує милі, галони й mpg, як в ATS.
- **WIPERS** переїхали в зону LIGHTS & SIGNALS під перемикач світла; HIGH BEAM і HAZARD знову звичайного розміру.
- **NAV** на місці WIPERS у нижньому ряду (NAV і FUEL ділять ряд навпіл): `routeDistance`, `routeTime`, `restStop`, `time_abs_delivery − time_abs`, `cityDst`, `plannedDistanceKm`. Проміжних чекпойнтів у телеметрії немає.

### Чистка панелі та годинник (Oct 10, 2026)

- **REST IN** показує, скільки миль можна проїхати до відпочинку: середня швидкість за останні 50 миль (`truckOdometer` + `time_abs`, ігровий час) × `restStop`. Зупинки довші за 10 ігрових хвилин не рахуються; стрибок годинника > 30 хв або одометра > 5 км (сон, пором, потяг, інше збереження) скидає вікно. Оцінка з'являється після 3 км і 5 хв їзди. Стан живе в пам'яті сервера (одна сесія).
- **DELIVERY**: замість «LEFT» — ігровий день і час дедлайну (`time_abs + залишок`).
- **CLOCK**: ігровий (`time_abs`, хвилини від 00:00 першого дня — понеділка) і реальний (годинник планшета) аналогові годинники поруч. Календарної дати гра не має — показується номер дня.
- **CAB & ACTION** (замість AXLES & ACTION і CAB): ACTIVATE, компактні BEACON / FRONT AUX / ROOF AUX зі станом OFF / DIM / FULL (SDK: 1 — dimmed, 2 — full), WIN DOWN / WIN UP, HORN. HORN зменшено з 305×160 до 86×122 px (−78%).
- ENGINE BRAKE, DIFF LOCK, LIFT AXLE, TRAILER AXLE сховано з екрана; конфіг, індикатори й SETUP без змін.
- Відкрите питання: з оновленням 1.60 гра має два лічильники — Rest State і Mandatory Break. Який з них віддає `restStop`, SDK не описує; треба звірити в грі.

### Планувальник доставки (Oct 11, 2026)

Клітинка **PLAN** у зоні NAV: маршрут вантажу розбитий на робочі дні, щоб встигнути до дедлайну, і видно, як ти йдеш по плану. Без ШІ, лише арифметика на телеметрії.

- **Робочий день** — зміна від пробудження до сну. Сон видно за `restStop`: він стрибає вгору на 2 год і більше. Довжина нової зміни береться з `restStop` після сну, тривалість сну — зі стрибка `time_abs`. До першого сну: зміна 11 год, сон 9 год (припущення, звірити в грі).
- **План від дедлайну.** Залишок (`routeDistance`, без GPS-маршруту — `plannedDistanceKm` мінус проїхане) ділиться між змінами, що вміщуються до `time_abs_delivery`, пропорційно до часу їзди в кожній. Ціль на сьогодні фіксується на початку зміни; наступні дні перераховуються на ходу.
- **Прогрес.** Проїхано за зміну (`truckOdometer`) / ціль; «AHEAD / BEHIND» — порівняно з тим, скільки мало бути на цю частку зміни (`restStop` на старті зміни → зараз). Зелений — у плані, бурштиновий — відстаєш більше ніж на 10% денної цілі, червоний — дедлайн минув.
- Новий вантаж (інше місто або дедлайн) починає план заново. Стан живе в пам'яті сервера, як REST IN.
- Те саме відкрите питання 1.60: `restStop` — Rest State чи Mandatory Break.

### Cab Deck 3D, v3 (Oct 13, 2026)

Окрема сторінка `/v3` (`static/v3.html`) поруч із класичною `/`, щоб порівняти. Увесь щиток — одна сцена three.js, HTML лишився лише для SETUP.

- **Рендер.** three.js 0.169 + pmndrs postprocessing 6.36 (HDR-буфер, MSAA, bloom з mipmap-розмиттям, віньєтка, тонмапінг Khronos Neutral, щоб фірмові кольори й кремові написи лишались точними). Освітлення: `RoomEnvironment` (PMREM) для відбиттів на металі, одне сонце з м'якими тінями. Фарбовані й пластикові поверхні відбивають оточення слабко, щоб зелений не вицвітав. Кадр малюється лише коли щось змінилось або йде анімація.
- **Текст.** troika-three-text (SDF) зі шрифтом Saira Semi Condensed — чіткий на будь-якому масштабі.
- **Анімація.** GSAP: пружні кнопки, тумблери, що відскакують від упору, витягування ручок, стрілки годинників і манометра; при старті камера «підіймає» щиток на місце, а стрілка манометра робить самотест.
- **Дотик.** Промінь від пальця шукає невидимі зони дотику. Протокол, мультитач, відпускання на `pointercancel` / `lostpointercapture` / приховування сторінки — як у класичній панелі.
- **Нове керування.** Двірники — повзунок у прорізі з фіксаторами (як важелі пічки Peterbilt 379), хромована лопатка з підсвіченою смужкою. Тягни або тапни по смузі; положення ставиться лише після відпускання пальця. (Спершу була поворотна ручка — на дотик вона виявилась незручною.)
- **Демо** `?demo` імітує стан у браузері й не відкриває сокет.
- **Обмеження.** Потрібен інтернет для CDN; на слабкому планшеті перевірити плавність і нагрів.
- **Правки після першого огляду (Oct 13, 2026).** Менше «мила»: bloom з жорстким порогом (світяться лише лампи й кришки, написи й метал лишаються різкими), темніші зони й колодязі ближче до класичного ALPHA, слабше заповнювальне світло. Тумблери на 15% більші, замість лампи збоку — світне кільце навколо тумблера. Двірники нижчі, HAZARD значно більша. ENGINE & AIR: PARK BRAKE і TRAILER AIR угорі, ENGINE під ними, усі три одного великого розміру. CAB & ACTION: усі кнопки, крім ACTIVATE, одного розміру й на ~25% більші.

## Етап 4: Alpha Gen — другий екран приладів (прототип, Oct 11, 2026)

Додатковий щиток приладів «класика, що пішла в майбутнє» для Peterbilt 379 на телефоні Galaxy S26 (горизонтально, ≈19.5:9). Cab Deck на планшеті не змінюється.

- **Порт.** Той самий процес `server.py` слухає ще порт 8701 (`--dash-port`); на ньому `/` віддає `dash/index.html`. Дані — WebSocket `/ws/dash`, лише від сервера до щитка, 60 разів на секунду: окремий цикл читає гру лише поки щиток підключений (Cab Deck лишається на 10 Гц). На щитку стрілка доганяє дані за ~25 мс замість ~100 мс у демо. Щиток нічого не надсилає і не може натиснути кнопку.
- **Поля SDK.** `speed` (м/с → mph), `engineRpm`, `gearDashboard` (0 — N, менше нуля — R), `airPressure` (psi), `fuel / fuelCapacity`, `oilPressure` (psi), `waterTemperature` (°C → °F), `cruiseControl`, `cruiseControlSpeed` (м/с → mph), `blinkerLeftOn` / `blinkerRightOn`, `parkBrake`, `motorBrake`, `differentialLock`, `lightsBeamHigh`, `truckOdometer` (км → милі).
- **Без гри** щиток крутить демо-поїздку з написом DEMO; живі дані перемикають його автоматично, а через 3 с без даних він повертається в демо.
- **Дизайн.** Фірмовий темно-зелений Cab Deck (`#153126` → `#0A1B14`), кремові цифри `#E4DCC4`, матові металеві обідки без штучних відблисків, сегментні шкали зі світінням, самотест стрілок при старті. Рендер — один фрагментний шейдер WebGL, без бібліотек і без збирання.
- **Розкладка для телефона (Oct 11, 2026).** Без хедера й футера: спідометр і тахометр на всю висоту екрана, малі прилади в чотирьох кутах, що їх кола лишають вільними. Поворотники — у верхній щілині між колами, лампи — у нижній і лише коли горять. Годинник і одометр прибрано.
- **Варіант 2 (Oct 11, 2026), порт 8702, `dash/v2.html`.** Порівняти з кільцями, не ламаючи v1. Шкали йдуть по ламаному контуру з м'якими кутами (DAF): рівний низ від нуля біля центру, фаски, нахилений бік, верх заходить глибше до центру й опускається. Суцільна заливка, розділювачі кожні 10 mph / 250 об/хв, тонка лінія на весь діапазон. Центр: велика швидкість, передача з поворотниками, іконка круїзу з виставленою швидкістю, лампи. Рендер на WebGL2: контур запікається в текстуру при завантаженні, світіння — bloom (6 рівнів розмиття) і м'яка тонова крива замість обрізання. Той самий `/ws/dash`.
- **Обмеження.** Телеметрія дає один тиск повітря, тож обидві стрілки манометра показують те саме значення.

- **Оздоблення ALPHA для Cab Deck (Oct 11, 2026).** Стиль v2 перенесено на панель з кнопками як нове оздоблення за замовчуванням (старі лишаються в SETUP → CONSOLE). Колір «увімкнено» йде з CSS `--ok` (м'ятний `#7BEFB5` в ALPHA), лампи — світні диски з багатошаровим світінням (CSS-аналог bloom: кнопки — HTML, WebGL їх не освітить), рамки зон — тонкі сатинові лінії, без відблисків, шрифт Saira Semi Condensed. Ключ збереження оздоблення змінено, щоб усі панелі один раз відкрилися в ALPHA.

- **Cab Deck: 3D-керування (Oct 12, 2026).** Лише в ALPHA. three.js 0.160 з CDN (importmap), одне прозоре полотно над `#dash` малює всі тумблери, кнопки й ручки у своїх рамках (scissor-viewport), перемальовує лише під час руху; HTML лишається зоною дотику й логікою. Без three.js — плоскі версії. LIGHTS: три тумблери (PARK, LOW BEAM — позиції перемикача світла; HIGH BEAM — тап-кнопка з оптимістичним перекиданням до 1.5 с). ENGINE — одна кнопка START/STOP; PARK BRAKE і TRAILER AIR — ручки «тягни-штовхай» зі світним кільцем стану. Решта кнопок — 3D-кнопки з підсвіченою кришкою, без станових підписів.

## Етап 5: оверлей поверх гри (Oct 12, 2026)

Дешборд v2 у прозорому вікні поверх ATS (як оверлеї iRacing), без мода. Мод щитка відкладено: UI гри не повторить живі шкали й bloom.

- **Вигляд:** за замовчуванням `?shape=1` — темний дешборд, обрізаний по силуету (зовнішній край кілець + запас 0.014; між кільцями — рівна лінія через їхні верхні кінці), довкола прозоро; маска рахується в сцені (зелений канал шару покриття). Плашку передачі опущено, щоб її верх лежав на цій лінії. Без параметра — прямокутна панель; `?overlay=1` — прозорий HUD.
- **Прозора сторінка:** `/?overlay` на порту 8702 — без фону консолі; сцена пише окремий шар покриття (MRT), фінальний прохід дає premultiplied alpha: лінії й цифри непрозорі, панелі напівпрозорі, світіння — власною яскравістю. Текст отримує темну тінь для читабельності.
- **Програма:** `overlay/` на Electron (Node 18+, без збирання; `overlay.bat` ставить залежності при першому запуску). Вікно прозоре, без рамки, завжди зверху (`screen-saver`), кліки крізь нього, без фонового троттлінгу. Ctrl+Shift+F10 — режим налаштування (перетягування власним кодом — `-webkit-app-region` на Windows ковтає колесо; колесо або +/− — розмір зі збереженням пропорцій; стрілки — зсув 1/10 px), Ctrl+Shift+F9 — показати/сховати; позиція й параметри в `overlay/overlay.json`.
- **Обмеження:** гра у віконному/безрамковому режимі; оверлей прибитий до екрана (не рухається з головою); рендер на тій самій відеокарті, що й гра.

# PRD: Cab Deck — планшетна панель керування для ETS2 (пілот)

Oct 4, 2026 · @Liub · v3 (vJoy, віддалена діагностика)

> Цільова гра — American Truck Simulator. ETS2 працює так само: той самий движок SCS, vJoy і SDK. Далі в тексті «ETS2» означає будь-яку з двох ігор.

## Суть і мета

Пілот перевіряє одну гіпотезу: кнопка, натиснута у браузері планшета, спрацьовує в Euro Truck Simulator 2 як кнопка окремого ігрового пристрою, без встановлення застосунку на планшет.

На ПК запускається Python-програма. Вона роздає веб-сторінку з панеллю кнопок у локальній мережі й перетворює дотики на натискання кнопок віртуального джойстика vJoy. Гра бачить vJoy як звичайний контролер, і дії на його кнопки призначаються в меню керування гри.

Кожна кнопка панелі має стабільний ID виду `cab_deck_btn_NNN`, де `NNN` — номер кнопки vJoy. Наприклад, `cab_deck_btn_007` — це кнопка 7 пристрою vJoy.

Пілот вважається вдалим, якщо за одну ігрову сесію панеллю можна керувати допоміжними функціями вантажівки (світло, двірники, поворотники, вікна) і не тягнутися до клавіатури.

## Межі пілота

| Входить у пілот | Не входить (наступні етапи) |
| --- | --- |
| Python-сервер на ПК з Windows | Власний плагін SCS SDK з іменованими входами |
| Віртуальний джойстик vJoy, лише кнопки | Осі vJoy: повзунки, кермо, педалі |
| Одна сторінка панелі на простому HTML/JS | React, кілька сторінок-табів |
| 12 кнопок двох типів: натискання й утримання | Перемикачі на кілька положень |
| Розкладка кнопок у JSON-файлі | Візуальний редактор панелі |
| Режим `--dry-run` для розробки без Windows і vJoy | Телеметрія з гри, підсвітка реального стану |
| Один планшет у домашній Wi-Fi мережі | Кілька пристроїв, доступ через інтернет |
| Індикатор з'єднання й автоперепідключення | Авторизація, HTTPS |

## Сценарій використання

Від запуску до першого натискання в грі має проходити не більше хвилини.

1. Користувач запускає на ПК одну команду: `python server.py`.
2. Сервер друкує в консолі всі локальні IPv4-адреси з портом: `http://192.168.x.x:8000`.
3. Користувач відкриває цю адресу в браузері планшета. Планшет і ПК в одній Wi-Fi мережі.
4. Панель показує сітку кнопок і зелений індикатор з'єднання.
5. Користувач запускає ETS2.
6. Дотик до кнопки на планшеті виконує дію в грі.
7. Якщо з'єднання зникає, індикатор стає червоним, а панель сама перепідключається.

### Одноразове налаштування

1. Встановити драйвер vJoy (форк, сумісний з Windows 10/11).
2. У `Configure vJoy` для пристрою 1 задати кількість кнопок не менше 32 (за замовчуванням їх 8).
3. Дозволити порт 8000 у брандмауері Windows для приватної мережі.
4. У грі: «Параметри → Керування» — додати vJoy як пристрій вводу й призначити дії на кнопки. Щоб призначити кнопку, у режимі призначення торкнутися її на планшеті.
5. На планшеті вимкнути автоблокування екрана.

## Архітектура

```
Планшет (браузер) ──WebSocket──► server.py ──pyvjoy──► драйвер vJoy ──► ETS2
                                     │
                                 config.json
```

Планшет шле лише ID кнопки й тип події. Сервер перевіряє ID за конфігом і сам вирішує, яку кнопку vJoy натиснути, тому з клієнта не можна передати довільний ввід.

### Стек

| Компонент | Технологія | Навіщо |
| --- | --- | --- |
| Сервер | FastAPI + uvicorn | HTTP і WebSocket в одному процесі |
| Ввід | vJoy + `pyvjoy` | Окремий ігровий пристрій, без конфліктів з клавіатурою |
| Панель | HTML, CSS, JS без збірки | Для пілота досить одного файлу |
| Конфіг | `config.json` | Розкладка без правки коду |

### Протокол

Повідомлення йдуть як JSON через WebSocket.

| Напрям | Повідомлення | Коли |
| --- | --- | --- |
| Сервер → планшет | `{"type": "layout", "grid": {...}, "buttons": [...]}` | Одразу після підключення |
| Планшет → сервер | `{"id": "cab_deck_btn_007", "event": "down"}` | Палець торкнувся кнопки |
| Планшет → сервер | `{"id": "cab_deck_btn_007", "event": "up"}` | Палець відпустив кнопку |
| Планшет → сервер | `{"type": "ping"}` → `{"type": "pong"}` | Кожні 2 с |
| Планшет → сервер | `{"type": "client_error", "message": "..."}` | JS-помилка на панелі |

Для кнопки `tap` сервер на `down` ставить кнопку vJoy у стан «натиснута» й відпускає її через `tap_ms` (типово 80 мс, щоб гра встигла побачити натискання навіть при низькому FPS). Подію `up` для `tap` сервер ігнорує. Для `hold` кнопка натиснута від `down` до `up` або до `hold_timeout_s`. Затримки реалізуються через `asyncio`, без блокування сервера.

### Конфіг

```json
{
  "vjoy_device": 1,
  "tap_ms": 80,
  "hold_timeout_s": 10,
  "grid": {"cols": 4, "rows": 3},
  "buttons": [
    {"id": "cab_deck_btn_001", "label": "Фари", "icon": "💡", "color": "#f5c542", "type": "tap"},
    {"id": "cab_deck_btn_007", "label": "Сигнал", "icon": "📯", "color": "#e05252", "type": "hold"}
  ]
}
```

Номер кнопки vJoy береться з ID: `cab_deck_btn_007` → кнопка 7. Окремого поля для номера немає, тож розійтися ID і номер не можуть. ETS2 рахує кнопки джойстика з нуля, тому в меню гри ця кнопка показується як Button 6.

### Файли проєкту

- `server.py`: сервер, WebSocket і модуль вводу (vJoy або dry-run)
- `config.json`: розкладка кнопок
- `static/index.html`: панель
- `requirements.txt`: залежності

- `spike_vjoy.py`: одноразова перевірка, що ETS2 бачить кнопки vJoy

## Нефункціональні вимоги

Головна вимога — затримка: від дотику до реакції в грі не більше 100 мс у домашній Wi-Fi мережі.

- **Платформа ПК:** Windows 10 або 11, Python 3.10+, встановлений vJoy.
- **Розробка:** сервер і панель розробляються на macOS у режимі `--dry-run`. Реальний ввід перевіряється на Windows-ПК.
- **Планшет:** будь-який сучасний браузер (Chrome на Android, Safari на iPad), без встановлення застосунків.
- **Мережа:** тільки локальна. Сервер не має бути доступний з інтернету.
- **Безпека:** сервер виконує лише дії з `config.json`. Довільний ввід з клієнта передати не можна, тільки ID кнопки.
- **Надійність:** жодна кнопка не лишається затиснутою після розриву з'єднання, закриття сторінки або зупинки сервера.
- **Запуск:** одна команда, залежності ставляться через `pip install -r requirements.txt`.
- **Розширюваність:** нова кнопка додається рядком у `config.json` і призначенням у грі, без правки коду.
- **Діагностика:** стан і лог сервера на Windows можна прочитати з Mac через `/api/health` і `/api/logs`, без доступу до екрана ПК.

## Ризики

Найбільший ризик — гра не бачить vJoy або не дає призначити дії на його кнопки. Його перевіряє `spike_vjoy.py` ще до верстки панелі.

| Ризик | Наслідок | Що робимо |
| --- | --- | --- |
| ETS2 не бачить vJoy або не призначає кнопки | Пілот не працює | Спайк першим кроком. Запасні варіанти: імітація клавіатури (`pydirectinput`) або власний плагін SCS SDK |
| Драйвер vJoy не ставиться на Windows 11 | Немає пристрою | Брати підтримуваний форк vJoy, описати версію в README |
| Версія `vJoyInterface.dll` у `pyvjoy` не збігається з драйвером | Помилка при старті | Підкласти DLL з папки встановленого vJoy, описати в README |
| У vJoy налаштовано лише 8 кнопок | Кнопки 9–12 не працюють | Крок у README. Перевірка S8 при старті |
| Гра ігнорує джойстик, коли вікно не у фокусі | Натискання не доходять | Перевірити в спайку. Якщо так, описати в інструкції |
| Брандмауер блокує порт | Планшет не відкриває сторінку | Правило для порту 8000 у приватній мережі, крок в інструкції |
| Кнопка «залипає» після розриву Wi-Fi або сну вкладки | Сигнал або вікно працюють безкінечно | Вимоги S5, S7 і P3 |
| Браузер планшета масштабує або прокручує сторінку | Хибні дотики | Вимоги P5 і P6, перевірка на реальному планшеті |
| Панель не знає реального стану (фари ввімкнені чи ні) | Кнопки без підсвітки стану | Прийнято для пілота. Телеметрія на наступному етапі |
| Будь-хто в домашній Wi-Fi може натискати кнопки | Випадкові дії в грі | Прийнято для пілота. Авторизація на наступному етапі |

## Етап 2: зворотний зв'язок з гри (у роботі)

Мета: кнопки панелі показують реальний стан вантажівки в грі.

### Джерело даних

Плагін RenCloud scs-sdk-plugin V.1.12.1 (`scs-telemetry.dll` у `<гра>\bin\win_x64\plugins\`) пише телеметрію в спільну пам'ять `Local\SCSTelemetry`. Сервер читає її через бібліотеку `truck-telemetry`. Одне читання займає ~0.8 мс, тож опитування 10 разів на секунду не навантажує ПК.

### Результати спайку (Oct 4, 2026, ATS, телеметрія гри 1.5)

| Кнопка | Поля телеметрії | Стани на панелі |
| --- | --- | --- |
| Двигун | `electricEnabled`, `engineEnabled` | вимкнено / запалювання / заведено |
| Фари | `lightsParking`, `lightsBeamLow` | вимкнено / габарити / ближнє |
| Дальнє світло | `lightsBeamHigh` | вимк / увімк |
| Лівий / правий поворотник | `blinkerLeftActive` + `blinkerLeftOn` (фаза), так само для правого | вимк / блимає в такт з грою |
| Аварійка | `lightsHazards` + фаза з `blinkerLeftOn` | вимк / блимає |
| Стоянкове гальмо | `parkBrake` | вимк / увімк |
| Двірники | `wipers` — лише увімк/вимк, режим не передається | див. відкрите питання |
| Причіп | `trailer[0].attached` | не перевірено |
| Ретардер | `retarderBrake` з `retarderStepCount` (3 на тестовій вантажівці) | не перевірено |
| Сигнал, вікна | немає в телеметрії | без стану |

Під час аварійки `blinkerLeftActive` і `blinkerRightActive` лишаються `False`, тому аварійку не можна визначати через поворотники.

### Рішення

- **Індикатори.** Сервер опитує телеметрію кожні 100 мс і зводить її до індикаторів з рівнем `off` / `dim` / `on` і необов'язковим текстом («Габарити», «Запалювання»). Кнопка в конфігу посилається на індикатор полем `"indicator": "lights"`. Поворотники й аварійка передають фазу блимання через `dim` / `on`.
- **Двірники — перемикач на 4 положення** (`"type": "switch"`). У ATS є лише дії «Двірники» (вперед) і «Двірники назад», тому панель сама пам'ятає положення. Торкання «3» з положення «1» дає два натискання «вперед». Між натисканнями `switch_gap_ms` (150 мс). Перемикач ніколи не тисне «вперед» на останньому положенні чи «назад» на «Вимк», тож поведінка гри на краях циклу не важлива.
- **Корекція по телеметрії.** Якщо через 1 с після останнього натискання гра показує `wipers: False`, а перемикач не на «Вимк», положення скидається в 0. Якщо двірники працюють, а перемикач на «Вимк», ставиться 1. Помилка можлива лише тоді, коли режим змінили повз панель, і вона виправляється при наступному вимкненні.
- **Стан гри на панелі:** «немає телеметрії» / «не запущена» / «пауза» / «в кабіні».

### Протокол етапу 2

| Напрям | Повідомлення | Коли |

## Етап 3: пневматика, додаткове світло, сторінки, гаптика (у роботі)

Рішення від Oct 4, 2026. Беремо пневматику й гальма, ACTIVATE, маячок і додаткові фари, сторінки, гаптику. Не беремо: круїз-контроль (є на кермі), інформаційну смугу, камери, радіо, місії.

### Сторінки

| Вкладка | Контроли |
| --- | --- |
| DRIVE | LIGHTS, HIGH BEAM, LEFT, RIGHT, HAZARD, WIPERS, HORN, ENGINE, PARK BRAKE, TRAILER AIR, ACTIVATE |
| AIR & BRAKES | AIR PRESSURE (прилад), RETARDER, ENGINE BRAKE, DIFF LOCK, LIFT AXLE, TRAILER AXLE |
| CAB | BEACON, AUX FRONT, AUX ROOF, WINDOW DOWN, WINDOW UP |

Інтерфейс англійською. Конфіг: `pages` замість `grid` + `buttons`.

### Телеметрія

| Контрол | Поля | Показ |
| --- | --- | --- |
| RETARDER | `retarderBrake`, `retarderStepCount` | точна позиція; зайві положення сховані |
| ENGINE BRAKE | `motorBrake` | вимк / увімк |
| DIFF LOCK | `differentialLock` | вимк / LOCKED |
| LIFT AXLE / TRAILER AXLE | `liftAxleIndicator`, `trailerLiftAxleIndicator` | вимк / RAISED |
| AIR PRESSURE | `airPressure`, `airPressureWarning`, `airPressureEmergency` | значення в psi, шкала, жовтий / червоний стан |
| BEACON | `lightsBeacon` | вимк / увімк |
| AUX FRONT / AUX ROOF | `lightsAuxFront`, `lightsAuxRoof` (0 / 1 / 2) | вимк / dim / on |

Бібліотека `truck-telemetry` перезаписує поріг `airPressureWarning` (float) прапорцем з тією ж назвою (bool). Нам потрібен лише прапорець, тож це не заважає.

### Перемикач з точною позицією

Ретардер — перемикач, як двірники (кнопки vJoy 18 «+» і 19 «−»), але з `"position_source": "retarder"`. Через 1 с після останнього натискання положення береться з гри. Ціль обмежується кількістю ступенів вантажівки: на 3-ступеневому ретардері дотик до «5» зупиниться на 3.

### Гаптика

`navigator.vibrate` на кожен дотик: tap 12 мс, hold 25 мс, сегмент перемикача 10 мс, кожне фактичне перемикання положення 6 мс, вкладка 6 мс, втрата зв'язку — подвійний імпульс. Працює в Android-браузерах. На iPad вібромотора немає, тому там гаптики не буде.

### Вкладка SETUP

Остання вкладка. Список усіх кнопок vJoy з конфігу, відсортований за номером: номер vJoy, номер у грі (на 1 менший), назва контролу, напрям для перемикачів і назва дії в ATS (`action`, `forward_action`, `back_action` у конфігу). Дотик шле `{"type": "bind", "key": "cab_deck_btn_013"}`, сервер робить одне натискання на 150 мс. Ключ звіряється зі списком кнопок конфігу, тож сирий номер передати не можна. Сторінки гортаються свайпом лише по смузі вкладок, щоб свайп не почався на контролі й не натиснув його.

### Критерії готовності етапу 3

- [ ] Кнопки vJoy 14–23 призначені в грі через вкладку SETUP
